### 🎨 [Palette Studio](https://github.com/TekiDeki/Palette-Studio)

**Every color, measured. Nothing uploaded.**

Pull a palette out of a photograph with k-means, build harmonies and gradients from it, and measure WCAG 2.x contrast with a suggestion for the nearest accessible color. The same palette is then shown through the eight most common color vision deficiencies, using all 33 matrices published by Machado, Oliveira and Fernandes (2009) applied in linear RGB. Export as CSS variables, Tailwind, SCSS, JSON, SVG or PNG.

Drop a PDF and take every page back as its own image, at 72, 150 or 300 dots per inch, JPG or PNG, or only the pages you list. The renderer is PDF.js, carried inside the page rather than fetched from a CDN, so a file is read and drawn on your own machine: no upload, no queue, no account, and the tool opens with the network off. The whole set goes down as one ZIP, and the size of the page in pixels is stated before you press the button.

JPG or PNG · 72, 150 or 300 dpi · page ranges · several files at once · one ZIP · locked PDFs · 4 languages · offline PWA

### 💬 [Subtitle Cleaner](https://github.com/TekiDeki/Subtitle-Cleaner)

**Subtitles that open cleanly, fixed in the tab.**

Drop an SRT or VTT and fix what a player complains about: cues that overlap are cut where the next one starts, a cue too long for two lines is split into pieces that share its time, the lines are re-wrapped under the limit you type, tags are stripped, and the whole file moves by a number of seconds or is retimed for a sped up video. The page reads the file itself, including a file saved in the old Windows encoding, so nothing is uploaded and no account is asked for.

SRT and VTT both ways · shift and speed · overlaps repaired · long cues split · line wrapping · tag stripping · report with counts · 4 languages · offline PWA

## 🧠 How I build

The priorities behind my tools:

| Principle | What it means |
|---|---|
| 🪶 **Dependencies with purpose** | Use well-chosen libraries when they improve quality. Keep them lightweight, bundle locally where practical, and respect their licenses. |
| 📄 **Single file** | One `index.html` holds the whole app. CSS and JS included. |
| 🔒 **Privacy first** | Most tools process data locally. Online speech voices may send text to their provider; each tool explains its own privacy limits. No app backend or analytics. |
| 📦 **Offline by default** | Service workers & web app manifests. Install it like a native app. |
| 🚀 **Free to host** | GitHub Pages. No servers, no bills. |
| 📱 **Mobile-first** | Big touch targets, responsive layout, light & dark themes. |

> *"The best code is the code you don't have to ship."*

### 🧰 Working on the hub

The 30 tool cards on [freeHTML.dev](https://freehtml.dev/) are not written by hand. They live in
[`tools.json`](tools.json), one entry per tool, and `python3 scripts/build-tools.py --write` renders
them into `site/index.html` at build time. The shipped page is still plain static HTML, with no extra
JavaScript, so the registry costs the visitor nothing.

    npm install                              # playwright, tests only
    python3 scripts/build-tools.py --check   # is the page exactly what the registry says?
    npm test                                 # registry, links, redirects

Adding a tool means one entry in `tools.json` plus its text in the four dictionaries. The tests fail
if a key is missing in any language, if a card's fallback text drifts from the English dictionary, or
if a short link (`/convert`, `/money`) is missing from `site/_redirects`.

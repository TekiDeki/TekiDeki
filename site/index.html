How I build

Six rules I don't break.

Constraints are the whole point. They keep the tools fast, cheap to host and honest about your data.

01

Single file

One index.html holds the whole app - markup, CSS and JavaScript together. Nothing to build, nothing to bundle.

02

Privacy first

Most tools keep data in your browser. Features that use external providers may send the relevant data to them; each app card explains when.

03

Offline, with one exception

Twenty-eight of the twenty-nine tools ship a service worker and a web app manifest: open one once, and it works on a plane, in a basement, on a farm. Games is the exception - its own security policy blocks service workers, so it needs a connection.

04

Mobile-first

Big touch targets, responsive layout, light and dark themes, no horizontal scrolling on a small phone.

05

Dependencies with purpose

A library only when it clearly improves quality - kept light, bundled locally where practical, licence respected.

06

Free to host

Static files on a free tier - GitHub Pages for the tools, Cloudflare's edge network for this site. No servers, no bills.

About

One person, one editor, no framework.

I'm Kristian Mario Mišković, @TekiDeki, writing code from Vršac, Serbia. I've been around long enough to remember when a website was a folder of files - and I still think that's a perfectly good way to build one.

These tools started as answers to small annoyances: which jar of coffee is actually cheaper, what BMI category am I in, how do I strip GPS data from 40 photos before posting them. None of them needed a server, so none of them got one.

If one of them saves you three seconds in a grocery aisle, a star on GitHub costs nothing - and a bug report costs even less.

What this site will never do

  • ✓No analytics, no tracking pixels, no advertising IDs.
  • ✓No cookies - so no cookie banner either.
  • ✓No accounts, no sign-up, no newsletter form.
